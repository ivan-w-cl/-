# 利物浦当地科普视频制作标准

这份标准来自第一期（EP01 利物浦天气与日照）的做法。工程模板在 `promo-video/explainers/ep01-weather/`，新的一期复制这个文件夹改。

一条合格的视频满足三件事：

1. **去掉产品介绍，科普本身仍然成立**，观众看完学到一件具体的事。
2. **每一个事实说得出来源**，每一个产品画面来自真实界面。
3. **改稿和换语言的成本很低**：旁白、画面文字、时间都是可编辑的。

## 流程

按顺序做。前一步没做完不要开始后一步，尤其是第 2、3 步不能跳过。

### 1. 定选题

- 从「刚到利物浦的人会困惑什么」出发，不从「产品有什么功能」出发。
- 一期只讲一个问题。把选题写成一句话问题，例如「为什么利物浦一天里会晴雨交替，白昼长为什么不等于日照多」。
- 再找一项和这个问题直接相关、已经上线的功能。找不到自然相关的功能，就换角度或换选题，不硬接。
- 可用的配对方向：
  - 天气与季节 → 日照参考
  - 校区分布 → 地图与通勤
  - 餐饮与配套 → 周边配套或餐饮卫生记录
  - 公开治安统计 → 周边资料

### 2. 查资料

- 优先用官方原始资料：天气用 Met Office，大学和公共服务用学校、市政府或运营方的官方页面。
- 每条事实记下：原话或数字、链接、地区、统计时段、核对日期。写进这一期的 `SOURCES.md`。
- 查不到当地数据时，用官方的上一级区域数据，并在画面上写明区域和时段。不编数字，不拿旧闻当新闻。
- 能算出来的（日出日落、太阳高度）自己算，把算法留在 `build.py` 里可复核，并在来源清单里标「计算所得」。
- 资料不足的说法删掉或缩小。不使用「最准确」「保证」「绝对安全」这类承诺。
- 如果官方网站打不开，只能看到搜索摘录，要在 `SOURCES.md` 开头写明，并提醒发布前人工核对。

### 3. 体验真实功能

- 把要展示的功能完整操作一遍，导出界面上的全部文字，包括工具自己写的适用范围和免责说明。
- 记下：能做什么、不能做什么、界面上的原话、可点的按钮和它们的选择器。
- 旁白对功能的描述以界面原文为准，不夸大。工具没有的计算不能说成有。
- 线上入口打不开时用离线 Web 包或真实录屏，不根据猜测补造操作。在来源清单里写明用的是哪一版。

### 4. 写旁白

结构（以 100 秒为例，按实际配音时长调整）：

| 段落 | 时长 | 要求 |
|---|---|---|
| 开场 | 约 8 秒 | 用一个具体的当地现象或事实直接进入，不用「你是不是也这样」这类套话，不虚构亲身经历 |
| 科普前半 | 约 35 秒 | 解释原因和背景，观众先拿到实质信息 |
| 产品中插 | 约 20 秒 | 只讲一项功能：怎么操作、带来什么具体便利、功能边界 |
| 科普后半 | 约 35 秒 | 补充实用知识或容易误解之处 |
| 结尾 | 约 5 秒 | 用知识结论收尾，不用口号，不加关注、购买、扫码等号召 |

写法：

- 写进 `script.json`，一句一行，按场景分组。一行就是一条字幕，尽量不超过 70 个字符。
- 数字写成读出来的样子（`about seven and a half hours`）。
- 科普段不提产品；中插第一句让观众明确知道接下来在介绍我们的工具。
- 产品名用「留学住宿通」，英文描述用 "Liverpool student accommodation mini program"，不自造英文品牌名。
- 英文版用自然清晰的英式男声，语速 1.25 倍。

### 5. 生成配音和时间

- 运行 `tts.py`，得到 `audio/voice.wav`、`audio/timing.json`（每句起止时间）和逐句 SRT。
- 之后所有画面的出现时机都引用 `timing.json` 里的句子时间，不写死秒数。这样改稿或换语言后画面自动对齐。
- 检查总时长在 80–120 秒，中插在 20 秒左右。超了就删句子，不要加快语速。
- 如果当前环境不能生成配音，如实告诉用户，不把静音视频当成已完成。如果生成了但自己听不到，也要说明并请用户试听。

### 6. 做画面

科普段（`scenes.js` 里的 `SCENES`）：

- 每个场景是一段按当前时间画出来的矢量图。讲到哪一句，对应的那一块才出现。
- 一个场景只表达一个意思，用地图、示意动画、条形对比、时间变化来讲，不用整屏文字卡轮流切换。
- 画面文字全部放进文件顶部的 `TXT` 表，不写死在绘图代码里。
- 版式：1080×1920。小标题和大标题在 y 250–450；图形在 470–1500；来源小字在 1490–1530；字幕在 1540–1760。
- 文字在手机上要读得清：大标题约 82px，图中正文不小于 28px，来源小字不小于 24px。
- 示意地图、示例数字、几何示意图都要在画面上标注（例如 "Schematic map"、"ILLUSTRATION · not a real forecast"）。
- 每个场景下方用小字写来源。科普段不露品牌，不放常驻 Logo。

产品中插：

- 手机框里运行真实网页，点按、拖动、切换都真实发生。用镜头推近和短暂停留让观众看清。
- 选中对象、打开工具、操作、看结果变化，按旁白的句子时间安排。
- 标注用界面上真实存在的元素做锚点。标注文字用视频语言，界面本身保留真实中文，不伪造英文界面。
- 讲功能边界的那一句，画面上同时出现提示条，并高亮工具自己的那句说明原文。
- 手机位置要让字幕不挡住关键操作。
- 中插结束后回到科普，不再展开其他功能。

### 7. 先出草稿，逐段看图

- 先用低帧率、低分辨率录一遍全片（每秒 5–10 帧），把各段抽帧拼成联系表，逐张检查。
- 常见问题：文字重叠或被裁切、标注跑出画面、字幕压住手机、某一段画面空着不动、字幕断句别扭、控制台里有「找不到元素」的警告。
- 全部修完再做正式渲染。不要跳过这一步直接出成片。

### 8. 正式渲染和混音

- 画面渲染两遍：带字幕、不带字幕（`EXTRA='&nocap=1'`）。30fps，1080×1920。
- 声音分三层：人声、背景音乐、点击音效。音乐比人声低 12–15 dB，人声出现时自动压低；整体响度 −14 LUFS，峰值不超过 −1.5 dB。
- 只用团队提供或有适用授权的音乐，在来源清单里写明曲名、作者和来源。

### 9. 交付

每一期交付这些文件：

- 完整成片 MP4（配音、字幕、音乐），另附一份 720p 小文件。
- 无背景音乐版（保留人声和音效）。
- 无字幕干净画面版，声音只有音乐和音效。
- 人声独立音轨；音乐加音效底轨。
- 旁白全文（按场景）、逐句 SRT、和画面字幕一致的 SRT、分场景时间表。
- `SOURCES.md`：事实、素材、配音、音乐来源，以及发布前需要人工确认的事项。
- 可编辑工程，按 `references/project-layout.md` 的结构。

交付时用几句话如实说明：哪些已经核实，哪些没能核实（听不到配音、网站打不开、用的是离线包），以及需要用户确认的地方。没验证过的不说成已验证。

## 验收清单

交付前逐条核对，见 `references/checklist.md`。任何一条不满足都要修，或者在交付说明里明确写出来。

## 做中文版

1. 翻译 `script.json` 的旁白，换中文音色重新生成配音；或用真人录音并填写 `audio/timing.json`。
2. 翻译 `scenes.js` 顶部的 `TXT` 表。
3. 运行 `build.py`，按第 7、8 步重新出草稿和成片。场景长度会跟着新配音自动调整。
