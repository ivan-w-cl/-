# 网站新功能交接说明：讨论语言 + 真人模拟准备卡 / 复盘卡

本包只包含新增和改动的文件，放进你们现有网站包的 `web-demo/` 文件夹即可。原来的其他文件都没有改。课程视频和课程内容不在本包里，由课程团队嵌入。

## 一、怎么看效果（3 分钟）

1. 打开你们的网站交接包（`esssouth-Web-Handoff-EN`）。
2. 把本包 `overlay/` 里的全部内容复制进 `web-demo/`。遇到同名文件选"替换"，一共 7 个文件：
   - `index.html`（替换）
   - `lessons/lesson01/index.html`（替换）
   - `discussion-moves.js`、`discussion-layer.js`、`discussion-layer.css`、`team-preview-demo.js`、`lessons/shared/moves-bridge.js`（新增）
3. 和以前一样启动：双击 `Start-Demo`，或运行 `node tools/serve-demo.mjs`。
4. 在浏览器打开 `http://127.0.0.1:8848/?demo=student`。
   - 这会用一个**演示学生账号**登录：「小周（示例）」，学校是西浦，带一条示例 AI 小组讨论记录，以及林老师的两次一对一模拟（一次在后天，一次已经结束）。
   - 打开 `/?demo=off` 回到原来的团队预览。
   - 演示账号不连接后端，只在你自己的浏览器里生效。

## 二、做了什么

| 功能 | 位置 | 说明 |
|---|---|---|
| 讨论语言（一套词） | `discussion-moves.js` | 所有讨论动作只在这一个文件里定义，AI 反馈、准备卡、复盘卡、课程卡片都从这里读 |
| 讨论语言页 | `#moves` | 从「练习」进入 |
| 5 分钟专项练习 | `#drill-<动作>` | 每个动作一题，示例题是为网站写的，不是课程内容 |
| 练习记录标注 | 练习记录详情页 | 在原有反馈上方加了「这次用到的讨论动作」，原有反馈保持不变 |
| 准备卡 | `#prep-<预约号>` | 从「今天」「我的」和预约详情弹窗进入 |
| 老师写复盘（演示） | `#teacher-<预约号>` | 正式版应放到老师后台，学生端不出现这个入口 |
| 复盘卡 | `#review-<预约号>` | 老师提交后出现在「今天」和「我的」 |
| 课程小节卡片 | `lessons/shared/moves-bridge.js` | 只读取播放器发出的事件，不控制播放器 |

所有新页面都沿用网站原有的样式和深色模式，手机宽度也检查过。

## 三、课程团队：怎么接一节新课

一节课接入讨论语言只需要改 `discussion-moves.js`，不用改页面代码。

1. 在 `LESSONS` 里加一课，`id` 要和这节课 `course-data.js` 里的 `lessonId` 一样：
   ```js
   { id: 'L02', title: '……', href: '/lessons/lesson02/index.html',
     sections: [ { id: 's01', title: '……', moves: [] }, { id: 's02', title: '……', moves: ['reason'] }, … ] },
   ```
2. 在 `MOVES` 里，把这节课教的动作的 `lesson` 设为 `{ id: 'L02', section: 's02' }`。没有设置的动作会显示"对应课程待录入"。
3. 在这节课的 `index.html` 里，紧跟 `course.js` 后面加一行（和第一课一样）：
   ```html
   <link rel="stylesheet" href="/discussion-layer.css"><script src="/discussion-moves.js"></script><script src="../shared/moves-bridge.js"></script>
   ```
   前提是这节课的播放器和第一课一样会发出 `ended` 事件，通道名要以 `course-v1` 结尾（第一课是 `esssouth-L01-course-v1`）。
4. 新的讨论动作：在 `MOVES` 里加一项（中文名、英文名、一句话说明、例句），再在 `DRILLS` 里加一道 5 分钟练习题。

**需要课程团队核对：** 第一课各节对应哪些动作、8 个动作的中文名，都是我按课程标题拟的初稿：
- s02 → 看清共同任务
- s03 → 提出具体建议
- s04 → 接住别人的话、追问澄清
- s05 → 邀请发言
- s06 → 条件变化后调整方案
- s01、s07 暂不对应动作

## 四、后端：需要接上的地方

演示版把下面的数据存在浏览器里，正式上线要改成存到服务器（预约系统已有 `/api/bookings`）：

| 数据 | 现在存在哪里 | 建议的接口 |
|---|---|---|
| 准备卡（重点、写给老师的话、是否共享记录） | 浏览器 `zp-mock-cards-v1` | `PUT /api/bookings/:id/prep` |
| 老师复盘（做得好的、下次重点、原话、一句话） | 同上 | `PUT /api/bookings/:id/review`（老师后台调用），`GET` 给学生看 |
| 练习原话共享给老师 | 只在学生本机 | 学生勾选同意后，老师后台才能读取最近 3 次讨论记录 |

**AI 反馈：** 现在每句话的讨论动作是用关键词规则标的（`discussion-moves.js` 里的 `tag()`），只用来演示。正式版请让 AI 只从 `MOVES` 的 `id` 里选，按「每句话 → 动作 id 列表」返回，页面不用改。

**老师端：** `#teacher-…` 页面只是演示复盘表单的样子，正式版请放进老师后台。

## 五、免费测试期和按学校收费

你们的代码里**已经有**这两个开关，这次没有重复做：
- **全站免费：** `/api/platform` 返回 `commerce: "free"` 时，所有课程显示「当前免费体验」。以后开始收费时把它改掉即可。
- **每个学校的试听课：** 每个课程产品的 `trialLessons`（可以试看前几讲），以及产品的 `school` 字段（西浦 / 港中深 / 上悉）。

新增的讨论语言、练习和准备卡 / 复盘卡都不涉及收费。真人模拟本身沿用原有的预约和收费流程。
